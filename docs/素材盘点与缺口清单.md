# 素材盘点与缺口清单（v0.4）

盘点对象：`icon/` 目录 48 个文件（1536² / 2048²，RGB，品红底）。

---

## 一、结论：能用的 / 有问题的

### ✅ 能用，而且质量不错

| 项 | 结果 |
|---|---|
| 抠图 | **48/48 全部可抠**。品红底干净（四角一致），底色占比 63–95% |
| 水印 | **48/48 全部可在不损伤主体的前提下擦掉**。水印固定在右下角，且逐张测过：没有一张的主体压到水印区（重叠率 0.0%） |
| 风格一致性 | 好。暗色 + 青蓝荧光 + 黄铜的统一语言，48 张看起来像一套 |
| 覆盖度 | 怪物、道具、主角（含 5 个动作帧）、地块、UI 几乎都覆盖到了 |

### ⚠ 有三个必须处理的问题

**1. 不是像素风，32px 显示会糊（最严重）**

这批是**精细插画**，不是像素画。同一素材在四个尺寸下的可辨识度：

| 尺寸 | 灯笼鱼 | 主角 | 结论 |
|---|---|---|---|
| 32px | 勉强认得出是鱼 | 认得出"戴圆盔的人" | 地图里当前用的就是这个 |
| 48px | 眼睛、牙齿出来了 | 干净利落 | **及格线** |
| 64px | 细节完整 | 很好 | 理想 |
| 96px | 完整 | 完整 | 图鉴/商店用 |

**根因不是分辨率，是显示面积。** 一张插画缩到 34px，能留下的只有剪影和大色块。这和素材做得多细无关。

**2. 暗色物体在深色地图上对比不足**

灯笼鱼、机械臂这类深蓝/近黑的素材，放进深色地图后直接融进去。原矢量图标有青蓝发光描边，真实素材没有。

**3. 文件名不规范**

- `主角潜水员 hero.png`、`灯笼鱼 mon‑anglerfish.png` 有空格
- 后者用的是 **U+2011 连字符**，不是普通 `-`
- 这两类文件名直接放进 `assets/sprites/` 会导致加载失败（已批量重命名）

## 三、还差哪些素材

### A. 补齐当前原型的硬缺口（3 个，优先级最高）

| 素材 | 为什么必须要 |
|---|---|
| **零件堆 / 螺栓螺母** | 游戏里 `G` 是"零件箱"，是金币位。芯片长得像芯片，不像可捡的钱 |
| **黄门** | 现在黄门用的是蓝色电子门，玩家分不清哪扇要黄卡哪扇要蓝卡。**颜色是通行证语言，不能含糊** |
| **下行梯 / 舱口** | 现在用"舱门"顶替，但舱门是横向开的门，"下楼"应该是垂直往下的井口 |

### B. 让画面立起来（2 个，优先级次之）

| 素材 | 说明 |
|---|---|
| **可平铺墙砖** | `tile-rock` 是单块石头，不是能铺满地图的墙面。地图现在是 canvas 程序化画的，能换就换 |
| **可平铺地板** | 同上，需要"金属舱板"质地的可平铺图 |

### C. 可选，锦上添花

| 素材 | 用途 |
|---|---|
| 主角待机 2 帧 | 现在 4 张动作图都有了，但游戏还没有帧动画系统 |
| 灯笼鱼动作 3 帧 | 同上（已经有了，等动画系统） |
| UI 九宫格面板 | 替换 CSS 画的弹窗 |

## 五、生产建议

1. **尺寸按 64px 出，不要按 32px。** 32px 是显示尺寸，不是生产尺寸。我们缩下去就行，反过来放大是救不回来的。
2. **优先做 A 组三个。** 这三个是"玩家会看出不对劲"的地方：捡到芯片以为是道具、黄蓝门分不清、上楼下楼一个图标。
3. **墙砖地板最后做。** 现在 canvas 的地形能撑住，换图是锦上添花。
4. **文件名只用小写字母、数字和普通 `-`。** 别用中文名、空格、全角符号。

## 六、一个需要你拍板的事

**32px 的格子，装不下这套插画的细节。**

两条路：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A. 保持 11×11** | 精灵在格子里当"剪影"用，细节只在图鉴/商店/预判弹窗里展示（那里有 100–200px 空间） | 地图上的怪物只能靠轮廓和颜色区分，认怪要靠点位位置 |
| **B. 缩小到 9×9 @ 40px** | 每格放大 25%，插画勉强能看 | 每层可见格数少 33%，规划感略降；关卡数据要重排 |

我倾向 **A**，因为"全图可见"是这个玩法的命根子，为了美术精度牺牲它不划算。而且图鉴本来就有放大的机会，玩家想看细节可以点开看。
