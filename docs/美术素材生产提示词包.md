# 《深潜五十》美术素材生产提示词包

> 用途：把原型里"矢量图标 + canvas 地形"的占位美术，换成真正能看的像素素材。
> 说明：本机没有可用的生图服务，下面的提示词**没有在此实测**。它们按像素素材的生产规范写，并附了"出图不对时怎么改"的对照表（第 7 节）。

---

## 0. 先说清楚缺口在哪

现在原型的状态：

| 部分 | 现在 | 需要 |
|---|---|---|
| 地形（墙/地板） | canvas 程序化绘制的像素石砖 | **能看，可以先不动** |
| 主角、怪物、道具、门 | SVG 矢量图标 | **主要缺口** |
| UI 面板、按钮 | CSS | 能用，想要更好可换九宫格图 |

所以**优先做第 4 节的 12 个精灵**，地形和 UI 排在后面。

---

## 1. 定风格：像素风，不要厚涂

11×11 全图可见 + 32px 格子，这两个约束决定了风格：

- **只有像素风能在 32×32 里保住"一眼认得出是什么"**。厚涂和 3D 渲染在这个尺寸下会糊成一团色块。
- 厚涂风格的细节（布料纹理、金属反射）在 32px 里全部消失，只剩下"一坨"。

三条硬指标，缺一条就不像游戏：

1. **1px 深色描边**包住整个轮廓（这是像素风的命）
2. **调色板 ≤ 12 色**
3. **无渐变、无模糊、无半透明**

---

## 2. 生产规格（不遵守会白做）

| 项 | 值 | 为什么 |
|---|---|---|
| 逻辑尺寸 | **32×32** | 与游戏格子 1:1 |
| 生成尺寸 | 512×512 或 1024×1024 | 模型画不出 32px，必须"大图小用"再缩 |
| 视角 | **正交俯视**（top-down），不是 45° 等距 | 我们的地图是正俯视，等距会歪 |
| 朝向 | 角色/怪物**朝向画面下方**（面对玩家） | 俯视游戏里背对玩家会读不出来 |
| 背景 | **纯品红 `#FF00FF`**（或纯绿，见 5.5） | AI 不理解"透明"，纯色底抠图最干净 |
| 边缘 | 硬边、无抗锯齿 | 缩小后抗锯齿会变成脏边 |
| 禁止 | 文字、水印、投影落到背景、外发光溢出格、多角度、多物件堆叠 | 任何一项都会让素材没法用 |

---

## 3. 全局风格锚（每次生成都要带上）

**风格前缀 S**（放在每条 prompt 最前面）：

```
16-bit pixel art sprite, top-down orthographic view, dark deep-sea industrial sci-fi,
limited palette of 10 colors, 1px dark outline, flat colors, hard edges, no anti-aliasing,
no gradient, no glow, centered single subject, magenta background #FF00FF
```

**负面词 N**：

```
blurry, gradient, glow, soft shading, 3d render, realistic, photo, text, watermark, signature,
multiple objects, character sheet, border, frame, drop shadow on background, isometric, perspective,
anti-aliased, semi-transparent, busy background
```

**参数**（按工具选一组）：

- Midjourney：`--ar 1:1 --style raw --v 6.1 --s 50`
- 即梦 / 豆包：直接贴英文提示词，风格选"像素/8bit"，比例 1:1
- Stable Diffusion：`Steps 30 / CFG 7 / Sampler DPM++ 2M Karras / 512×512`，可加 LoRA `pixel-art-xl`

## 4. 十二个精灵（优先做这一批）

### 4.1 主角 · 潜水员

> 说明：全身、正面、站在格子中央、脚不超出格底。要有辨识度——玩家要在一片暗色里一眼找到自己。

```
[S] a deep-sea diver in a worn brass diving helmet with a round glass porthole,
heavy canvas suit, holding a compact cutting torch in the right hand,
standing upright, facing the viewer, full body, feet at the bottom edge
```

### 4.2 怪物 ×4

建议**一张图表出四只**，风格最统一：

```
[S] a 2x2 sprite sheet of four different deep-sea creatures, evenly spaced grid,
same scale, same lighting: (1) anglerfish with a glowing lure, (2) swarm of pale blind shrimp,
(3) giant octopus head with two tentacles, (4) runaway industrial robotic arm with a cutting blade
```

出图后按 2×2 等分切，每只缩到 32×32。
如果四只大小不一，改用单只分别生成，并在 prompt 末尾加 `same scale as a 32x32 tile`。

### 4.3 道具 ×5

```
[S] a small yellow keycard with a black stripe, flat, slightly angled top-down
[S] a small blue keycard with a black stripe, flat, slightly angled top-down
[S] a dented steel oxygen canister, brass valve, standing upright
[S] a cutting torch blade upgrade, glowing cyan edge, mounted on a small bracket
[S] a stack of three steel armor plates riveted together
[S] a pile of five brass hex nuts and bolts
```

### 4.4 门与楼梯

```
[S] a heavy airlock door, yellow-and-black hazard stripes, closed, front view, filling the tile
[S] a heavy airlock door, deep blue, closed, front view, filling the tile
[S] a dark stairwell opening going down, metal ladder rungs visible, top-down
```

### 4.5 墙与地板（可选，想更好再做）

```
[S] a seamless tileable stone wall texture, 4x4 repetitions in the image, dark teal-gray stone,
riveted metal seams every 16 pixels, top face slightly lighter, sharp pixel edges
```

地板：

```
[S] a seamless tileable dark metal floor plate, 4x4 repetitions, near-black teal,
faint rivets at the corners, subtle grain
```

### 4.6 UI 九宫格（最后做）

```
[S] a 9-slice UI panel frame, dark gunmetal metal plate, thin cyan trim, 48x48,
16px corners, flat, no text
```

## 5. 一致性：比提示词更重要的事

模型每条 prompt 都会重新"猜"一次风格，光靠文字锁不住。三件套：

1. **先出一张风格锚图**——挑一张主角或墙砖，你满意的那张，命名为 `ref-style.png`。
2. **后续全部带参考图**：
   - Midjourney：`--sref ref-style.png --sw 200`
   - 即梦 / 豆包：用"参考图 / 风格参考"上传
   - SD：IP-Adapter 或 img2img（denoise 0.55）
3. **固定 seed**：同一批素材用同一个种子，只改描述。

> 经验：**参考图的作用远大于提示词**。如果只能做一件事，做参考图。

## 5.5 水印规避与抠图底色

### 为什么不能靠提示词去水印

豆包这类工具的水印是**生成后在图上叠加的**，不在模型的绘制范围内——你在 prompt 里写 `no watermark` 对它无效。唯一的办法是：**让主体别占满画面，把水印所在的四周裁掉。**

### 留白比例（关键数字）

| 环节 | 数值 | 说明 |
|---|---|---|
| 生成尺寸 | 1024×1024 | |
| 主体占画面 | **40–45%** | 提示词写 `occupying only 45% of the frame height` |
| 四周留白 | 各 ≥ 17% | 水印一般落在最外 10%，裁掉 17% 一定干净 |
| 裁切 | 保留**中间 65%**，四边各切 17.5% | 1024 → 666×666 |
| 裁后主体占比 | ≈ 69% | 剩下的再做一次透明边界裁切即可 |

这样做的代价是**有效分辨率下降**：1024 的图裁完只剩 666，缩到 32px 时是 20× 降采样。对 32×32 精灵来说完全够用——真正的限制是"轮廓能不能一眼认出"，不是像素数。

### 留白对应的提示词片段

加在每条 prompt 末尾：

```
subject centered, occupying only 45% of the frame height,
large empty margin of solid background on all four sides,
nothing in the corners, no border, no frame, no text, no logo
```

负面词补上：

```
watermark, logo, text, signature, corner decoration, frame, border, stamp
```

> 注意：留白一大，模型容易"手滑"在角落画点装饰。如果反复出现，把 `nothing in the corners, plain empty background` 再重复一遍，权重会更稳。

### 抠图底色：绿幕还是品红

结论：**你这套美术建议用品红 `#FF00FF`，不建议绿幕。**

原因是配色本身：

| 底色 | 风险 | 说明 |
|---|---|---|
| 绿 `#00FF00` | **高** | 这套游戏的招牌色就是青绿（`#2FD9CF`、`#38BDF8`）。灯笼鱼的诱光、气瓶的发光边、楼梯口的冷光全是青绿系，绿幕会把它们和背景一起抠掉，或留下绿边 |
| 品红 `#FF00FF` | **低** | 全项目调色板里没有任何品红色（黄卡 `#E0B341`、低氧 `#F59E0B`、青绿、深蓝灰）。抠图不会误伤 |

如果豆包对绿幕的抠图效果明显更好（有些工具对绿幕做了专门优化），可以用，但注意两点：

1. 用 **`#00FF00` 纯亮绿**，不要用暗绿——亮绿离青绿更远，误伤少一点
2. 出图后重点检查**发光边缘**：凡是原本有青绿光晕的地方，抠完容易成锯齿状缺口

两版提示词结尾：

```
[品红] on a solid pure magenta (#FF00FF) background, flat, no shadow falling on the background
[绿幕] on a solid pure green screen (#00FF00) background, flat, no shadow falling on the background
```

### 更省事的一条路

如果水印实在碍事，**把四个怪物排成 2×2 一张图**：主体相对画面更小，水印一定落在边角，裁一次能去掉四个的水印，还顺带解决风格一致性问题。缺点是四只的间距和大小要手动调，见 7 节。

## 6. 后处理（决定能不能用）

> 下面第 0–4 步已经写成脚本：`tools/prep_sprite.py`，一条命令跑完（裁水印 → 抠底 → 裁边界 → 缩 32）。
> 只有第 5、6 步（对齐、命名）还需要手动。
>
> ```bash
> python3 tools/prep_sprite.py raw/anglerfish.png -o assets/sprites/mon-anglerfish.png
> python3 tools/prep_sprite.py raw/*.png -o assets/sprites/ --key green --crop 0.2
> ```
>
> 参数：`--key` 选 `magenta`/`green`/`blue`，`--crop` 是四周各裁掉多少（默认 0.175），
> `--tol`/`--soft` 调抠图容差。不给 `-o` 就输出 `xxx_32.png` 先看效果。

0. **先裁水印**：把 1024 的图居中裁成 666×666（四边各切 17.5%），把角上的水印切掉再抠图
1. **抠底色**：PS 里 `选择 > 色彩范围` 点品红（或绿），容差 30，删除 → 导出 PNG（保留透明）
2. **缩放到 32×32**：必须用 **最近邻（Nearest Neighbor）**，绝对不能用双三次
3. **裁到内容边界**：去掉透明区域后再缩，保证主体铺满 32×32，否则精灵会显得小一圈
4. **检查轮廓**：缩到 32px 后如果认不出是什么，回第 4 步重生成——不要靠后期修
5. **对齐**：角色脚底贴格子底边，道具居中，门填满整格
6. **命名**：

```
assets/sprites/hero.png
assets/sprites/mon-anglerfish.png
assets/sprites/mon-shrimp.png
assets/sprites/mon-octopus.png
assets/sprites/mon-arm.png
assets/sprites/item-keycard-yellow.png
assets/sprites/item-keycard-blue.png
assets/sprites/item-oxygen.png
assets/sprites/item-cutter.png
assets/sprites/item-armor.png
assets/sprites/item-scrap.png
assets/sprites/door-yellow.png
assets/sprites/door-blue.png
assets/sprites/stairs.png
```

系统会自动优先加载 `assets/sprites/` 下的同名文件，没有就退回内置矢量图标。

## 7. 出图不对时的对照表

| 现象 | 原因 | 改法 |
|---|---|---|
| 变成模糊的厚涂/3D | 模型默认倾向写实 | 前缀加 `8-bit pixel art, 32x32, dithering`，负面词加重 `3d, render, smooth` |
| 出现"像素风"滤镜但仍是大图细节 | 只加了风格词没限尺寸 | 加 `32x32 pixels, low resolution, chunky pixels` |
| 背景不是纯品红 | 模型忽略了 hex | 改成 `on a solid magenta (#FF00FF) background, no scenery` |
| 四只怪物大小不一 | 网格图常见 | 改成单只生成，末尾统一加 `same scale as a 32x32 tile` |
| 角色朝向侧/背 | 俯视游戏常见歧义 | 明确 `facing the viewer, front view, looking down` |
| 边缘发虚 | 抗锯齿 | 负面词加 `anti-aliasing, soft edges`，后期用最近邻缩小 |
| 每个道具风格差很多 | 没带参考图 | 用第 5 节参考图锁风格 |

**验收清单**（对着原型逐条看）：

- [ ] 缩到 32px 后，每只怪物在不用看名字的情况下能认出是什么
- [ ] 主角在全屏 11×11 里第一眼能找到
- [ ] 所有精灵的描边粗细一致（都 1px，不能有的 2px 有的没有）
- [ ] 调色板整体不超过 12 色，没有突然冒出的高饱和色
- [ ] 放到暗色地图上，没有"贴纸感"（即边缘没有白边/黑边）
