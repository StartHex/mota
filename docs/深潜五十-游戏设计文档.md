# 《深潜五十 DIVE 50》游戏设计文档 v0.3

> 竖屏 · 单指 · 魔塔式资源约束玩法 · IAA 广告变现 · TapTap H5 发行
> 本文档用于确定**玩法骨架、界面结构、广告点位**三件事，不涉及最终美术与完整数值。

## 零、v0.3 重构：改名 + 换形态 + 换角色

### 0.1 为什么必须改

三条理由叠加，任何一条单独都够：

1. **商标与同名**：国内存在「魔塔世界」等商标注册先例与多款同名/近似作品，第 9 类（软件）、第 41 类（在线游戏）都是高风险区。
2. **审核红线**：TapTap 1.4.1 明确禁止「内容相似 / 雷同」的游戏。名字改掉但界面、怪物、文案照搬，一样会被判雷同——**只改皮不改骨，等于没改**。
3. **搜索与转化**：TapTap 搜索「魔塔」出来的是一堆 2018 年的老作品，新品排不进去；玩家也会默认这是山寨。

### 0.2 三个被否掉的改名方向（记录理由）

| 方案 | 为什么否 |
|---|---|
| 提灯 / 灯油 系（《提灯下井》《油尽之前》） | 机制上极好（灯油天然=HP），但 **《提灯与地下城》**（App Store id1507356201）已把「提灯 + 向下探索」这个联想占死，容易被判蹭热度 |
| 中式志怪（香火 / 阳气 / 三把火） | 文化辨识度高，但**「封建迷信」是版号与备案的常见卡点**，与「一次过审」的目标冲突 |
| 保留「塔」字做变体（《塔之囚》《五十层》） | 「塔 + 50 层」的组合仍在原版射程内，雷同判定风险不降 |

### 0.3 定案：深海救援

> 钻井平台 **「白鲸号」** 在 2500 米深处失联。事故后第 7 天，你作为应急潜水员下潜。
> 平台竖直卡在海沟里，从上到下 50 层舱段。**你只有一罐气，而且不能上浮。**

这个设定不是换皮，它**顺手解决了原版三个说不通的地方**：

| 原版的问题 | 深海设定如何天然解决 |
|---|---|
| 为什么不能回头 / 为什么一命到底 | 水压 + 单罐氧气，**物理上就上不去**，比「塔门关了」硬气得多 |
| HP 是什么 | **氧气**。战斗不再抽象——你在和生物/机械纠缠时消耗的是气 |
| 为什么不知道怪物数值 | **没有光**。声呐是主动技能，要耗氧（或看广告） |
| 为什么有商店 | 沉船里的补给柜，用打捞的零件换 |
| 为什么有钥匙门 | 船员的门禁卡（黄卡/蓝卡），权限分级 |

### 0.5 广告点位的语义重写（点位不变，说辞全换）

点位编号、占比、频控规则全部沿用第五章，只换玩家看到的语义——**这一步比换名更值钱**：

| 点位 | 原说辞 | 新说辞 | 为什么更好 |
|---|---|---|---|
| R1 战败复活 | 「满血复活」 | **「投放备用气瓶」**：从水面吊一罐下来，满氧继续 | 广告动作在剧情里成立，不像凭空回血 |
| R2 楼层回溯 | 「回到第 N 层」 | **「减压舱」**：回到已通过舱段的快照 | 有物理依据，不再是作弊 |
| R4 路线提示 | 「提示」 | **「主动声呐」**：扫出本层威胁与可达区域 | 与「信息类广告」铁律严丝合缝 |
| R3 一键扫荡 | 「扫荡」 | 「快速通过已清空舱段」 | 不变 |

> **铁律不变：广告只兑换 时间 / 信息 / 容错，绝不兑换 资源 / 数值 / 胜利。**
> 新增机制「主动声呐」必须同时存在**免费版**（消耗一点氧气看邻格），否则 R4 就变成了「信息付费墙」。

### 0.6 什么没变（这才是"抄得对"的部分）

- 战斗公式一字不改，`ATK − DEF ≤ 0` 就是打不过的硬门槛。
- 11×11 全图可见，不做镜头跟随。
- 50 层 = 5 章 × 10 层，每章末 Boss。
- 每层自动存档 + 三层容错 + R1/R2 挂在重来成本上。
- 无经验值、无养成、无刷怪，属性只来自拾取与商店。

## 一、产品定位

| 项 | 内容 |
|---|---|
| 暂定名 | 《深潜五十》（英文 DIVE 50；宣发语「氧气不多了」） |
| 类型 | 策略解谜 RPG（伪 RPG，本质是资源约束下的路径规划） |
| 屏幕 | **竖屏 9:16**，单手操作 |
| 单局时长 | 首次通关 2–4 小时；平均会话 6–12 分钟 |
| 目标用户 | ① 玩过原版《魔塔》的 25–35 岁怀旧用户 ② 喜欢数独/推箱子/纸嫁衣的解谜用户 |
| 对标 | 原版《魔塔 50 层》、TapTap 上的《魔塔》重制版、《不思议迷宫》的轻量化部分 |
| 变现 | IAA 为主（激励视频 + 插屏 + 开屏），可选 6–12 元内购去广告 |
| 一句话卖点 | **氧气只够一次选择。**（每一步都在算账，每张通行卡都是一次抉择） |

### 差异化在哪

原版《魔塔》在手机上有一个致命问题：**一命到底，走错一步 = 重玩两小时**。这在 2004 年的 PC 上是硬核，在 2026 年的手机上就是卸载理由。

我们的核心改造只有一句话：

> **把"不可逆的失败"改成"有代价的容错"，然后把广告挂在这个"代价"上。**

这一条同时解决了三个问题：移动端体验、留存、变现。后面所有设计都从这里推导。

## 二、核心玩法

### 2.1 战斗规则（沿用原版，务必不要改）

```
玩家每回合伤害 = max(0, 玩家ATK − 怪物DEF)
怪物每回合伤害 = max(0, 怪物ATK − 玩家DEF)
回合数         = ceil(怪物HP / 玩家每回合伤害)
战斗损失HP     = 回合数 × 怪物每回合伤害
```

**三条铁律：**

1. `玩家ATK − 怪物DEF ≤ 0` 时，**打不过**（伤害为 0，回合数无穷）。这是魔塔最重要的一条：它让"攻击力"成为硬门槛，而不是软收益。
2. 伤害差为 1 时，回合数爆炸：HP 100 的怪要打 100 回合，损失血量是伤害差为 10 时的 **10 倍**。所以数值设计必须保证 `ATK − DEF ≥ 5`，否则曲线会失控。
3. 战斗**无随机、无暴击、无闪避**。玩家的每一次失败都必须是"算错了"，不能是"运气不好"。这是本作和市面上一堆放置游戏的根本区别。

### 2.2 资源

| 资源 | 获取 | 消耗 | 设计作用 |
|---|---|---|---|
| HP | 红药水、升级、楼层奖励 | 战斗 | 唯一的"试错预算" |
| ATK | 攻宝石、商店、升级 | — | 突破怪物 DEF 门槛 |
| DEF | 防宝石、商店、升级 | — | 线性降低每次战斗损耗 |
| 金币 | 打怪、宝箱 | 商店买钥匙/属性 | 与钥匙竞争，制造取舍 |
| 黄钥匙 | 拾取、商店 | 黄门 | 高频小额决策 |
| 蓝钥匙 | 拾取、商店、Boss 层 | 蓝门 | 中频决策 |
| 红钥匙 | 稀有，Boss 掉落 | 红门 | 低频高价值决策 |

**建议砍掉经验值。** 原版的经验升级在手机上会让 HUD 过载，而且"自动升级"没有决策快感。改成：打怪只给金币，属性全部来自宝石/商店/楼层奖励。认知负荷降一半，策略深度基本不变。

> 如果一定要保留成长感：金币累计到阈值自动 +1 ATK / +1 DEF（不显示经验条，只显示"下一档还差 X 金"）。

### 2.3 地图元素

每层固定 **11 × 11** 网格。

| 类别 | 元素 |
|---|---|
| 地形 | 墙、地板、暗墙（撞一下才显示）、毒沼（每步 −5HP）、岩浆（不可通行） |
| 门 | 黄门、蓝门、红门、铁门（需破墙镐） |
| 怪物 | 约 20 种，分 5 个强度档 |
| 道具 | 红药水、蓝药水（回蓝？不需要）、攻宝石、防宝石、钥匙、破墙镐、传送卷轴、飞行器 |
| NPC | 商人（卖钥匙/属性）、老人（给情报）、小偷（开锁） |
| 机关 | 压力板、传送阵、可推动石块 |
| 出入口 | 上楼楼梯、下楼楼梯（**允许下楼，这是容错的一部分**） |

### 2.4 关卡结构：50 层 = 5 章

| 章节 | 楼层 | 主题 | 新增机制 | 难度定位 |
|---|---|---|---|---|
| 一 | 1–10 | 塔基·腐锈地牢 | 基础门/钥匙/怪物 | 教学，保证 90% 玩家能到第 10 层 |
| 二 | 11–20 | 毒沼回廊 | 毒沼、暗墙、商人 | 开始需要规划路线 |
| 三 | 21–30 | 熔火熔炉 | 岩浆、破墙、传送 | 硬核，需要算资源 |
| 四 | 31–40 | 镜像迷宫 | 传送阵、分身、双向门 | 最容易弃坑的区间，必须做好提示 |
| 五 | 41–50 | 王座之间 | Boss 连战、限时机关 | 通关率控制在 8–15% |

- 每章末尾一个 **Boss**（第 10/20/30/40 层），第 50 层是白鲸号驾驶舱 + 最终 Boss。
- **Boss 层自动存档**，且 Boss 战失败可以原地重试（不看广告，直接重试）——Boss 是"操作/数值检验"，不是"路线检验"，不该惩罚重来。
- 通关后解锁 **无尽模式 / 每日挑战**（随机种子 + 排行榜），这是留存主力。

### 2.5 每层设计检查清单（做关卡时必须逐条过）

- [ ] **可解性**：从进入该层的资源状态出发，存在至少一条通关路径（用求解器验证，见 §9.3）
- [ ] **非唯一性**：至少有 2–3 条可行路线，避免变成"背版"
- [ ] **无真死局**：不存在"用了这把钥匙就永远过不去"的设计。可以有"走错要绕远"，不能有"走错就死"
- [ ] **数值冗余 ≥ 20%**：最优解通关时剩余 HP 不低于 20%
- [ ] **至少一个"啊哈"时刻**：暗墙、绕后、用传送阵跳过、用毒沼换钥匙
- [ ] **广告点位不破坏最优解**（见 §5.2 的验证方法）

## 三、移动端改造：三个死穴和解法

### 死穴 1：方向键 → 手指

**问题**：11×11 的网格，虚拟摇杆精度差，走错一格要重来。

**解法**：**点击即寻路**。
- 点击相邻格 → 走一步
- 点击远处格 → A\* 自动寻路走过去（**遇怪即停**，不会自动开战）
- 长按任意格 → 显示该格信息（怪物属性 / 道具说明）
- 支持"按住方向滑动"作为老玩家的快捷操作

> 这一个小改动能让操作体验从"难受"变成"丝滑"，优先级最高。

### 死穴 2：一命到底 → 层存档

**问题**：手机是碎片场景，玩家随时被打断。一死重来 50 层 = 直接卸载。

**解法**：**每层自动存档 + 三层容错**

| 层级 | 机制 | 代价 | 是否收费 |
|---|---|---|---|
| L1 | 下楼 | 免费 | 否 |
| L2 | 回到本层起点（保留本层已得金币） | 免费，每层 1 次 | 否 |
| L3 | 回到指定楼层（完整状态快照） | 看 1 个激励视频，或内购解锁无限 | **是** |

> 注意：L3 的"回到指定楼层"是把玩家**送回那个时刻的完整状态**（HP/金币/钥匙/已拾道具全部还原），不是"带着现在的资源回去"。否则等于给资源，会破坏数值。

### 死穴 3：数值黑箱 → 战斗预判

**问题**：原版玩家要心算 `ceil(HP/(ATK−DEF)) × (ATK−DEF)`，手机上没人愿意算。

**解法**：**点怪物即显示预判结果**（免费功能，不是广告点）

```
┌──────────────────────┐
│  👹 骷髅战士          │
│  HP 100  ATK 35  DEF 5│
│  ──────────────────  │
│  预计损失  375 HP     │
│  预计收益  12 金      │
│  ⚠ 不划算（HP 只剩 40%）│
└──────────────────────┘
```

这个面板要给出**结论**（"可战 / 不划算 / 打不过"），而不只是数字。它把"心算"变成"判断"，是移动端最重要的一处现代化。

> 注意：面板**只显示当前属性下的预判**，不显示"如果你先拿宝石会怎样"。后者属于攻略，要留给广告提示（§5.2 R4）。

**为什么全图可见而不做镜头跟随：**
魔塔的乐趣是"一眼看完整层，然后规划路线"。缩小到能看全 11×11，是这个品类在手机上的正确形态。镜头跟随会毁掉规划感。

**信息优先级**：HP > 楼层 > 钥匙 > 金币 > 攻防。HP 是唯一"会死"的资源，必须最大。攻防可以在战斗预判面板里看，不必常驻。

### 4.2 视觉基调

| 项 | 方案 |
|---|---|
| 风格 | **高清像素**（不是复古低清），32×32 基准，整数倍缩放 |
| 主色 | 舱壁 `#0C1320` / 声呐青 `#38BDF8` / 氧气条 `#0E7C86 → #2FD9CF` |
| 强调色 | 黄卡/黄门 `#E0B341`、蓝卡/蓝门 `#2F6FB5`、低氧警告 `#F59E0B` |
| 字体 | 数字用等宽像素字体；中文用思源黑体 Bold（像素中文字体可读性差，不要硬上） |
| 动效 | 移动 120ms 位移；战斗 1 帧红闪 + 伤害数字弹出；**不做回合动画** |
| 音效 | 脚步、开门、受击、拾取、上楼，各 1 个即可 |

> **战斗绝对不要做成回合动画。** 一场战斗要结算几十回合，做成动画就是灾难。点击 → 立刻出结算面板（0.3s）是唯一正确解。
>
> v0.3 换色说明：原型用「暖金 + 石褐 → 深海青蓝」的整色相旋转落地，`#C9A227` 一族统一旋到 197°，保留明度关系只换色相，因此所有阴影/高光的层次都不用重调。**黄卡与蓝卡必须留在暖色**，否则通行证的颜色语言会塌。

### 4.3 关键页面流程

```
启动
 └→ 开屏广告（可跳过 2s）
     └→ 主菜单
         ├→ 继续游戏 → [楼层选择 / 最近存档]
         ├→ 新游戏 → 难度选择（普通 / 硬核）
         ├→ 图鉴 · 成就
         ├→ 每日挑战（通关后解锁）
         └→ 设置（音效 / 震动 / 去广告 / 隐私）
```

### 4.4 战斗结算面板（出现频率最高的界面，要打磨）

```
┌────────────────────────────────┐
│         ⚔ 战斗胜利             │
│                                │
│      👹 骷髅战士               │
│                                │
│   −375 HP    +12 💰            │
│   ████████░░░░░░  905/1280     │
│                                │
│         [ 确定 ]               │
└────────────────────────────────┘
```

- 只显示**变化量**和**结果 HP**，不显示回合数（玩家不关心）
- 如果这场战斗会致死 → 面板变成红色警告，并给出「取消 / 硬打」两个按钮（**允许玩家反悔，这是容错的一部分**）

### 4.5 「战败」面板（商业化最关键的一屏）

```
┌────────────────────────────────┐
│           💀 你倒下了           │
│                                │
│   生命耗尽，本层进度已保存      │
│                                │
│  ┌──────────────────────────┐  │
│  │ ▶ 看广告 · 满血复活       │  │  ← 激励视频，最高价值
│  │   保留全部进度            │  │
│  └──────────────────────────┘  │
│  ┌──────────────────────────┐  │
│  │   回到本层起点（免费）     │  │  ← 免费兜底，不能没有
│  └──────────────────────────┘  │
│  ┌──────────────────────────┐  │
│  │   回到指定楼层（需道具）   │  │
│  └──────────────────────────┘  │
└────────────────────────────────┘
```

**必须有一个完全免费的出口。** 否则会被 TapTap 审核判定为"诱导"（§8 引用 1.3.2），也会被玩家打一星。

## 五、广告设计（核心章节）

### 5.1 第一原则

> **广告只能兑换三种东西：时间、信息、容错。**
> **永远不能兑换：资源、数值、胜利。**

这条原则可以从魔塔的数学本质推导出来：魔塔是一个**受约束的优化问题**，最优解是唯一的（或少数几个）。任何"直接给资源"的广告，都等于把答案告诉玩家，游戏当场死亡。

| 广告给什么 | 后果 |
|---|---|
| ✅ 时间（扫荡、跳过） | 玩家更爽，数值不变 |
| ✅ 信息（提示、预判） | 降低门槛，不降低深度 |
| ✅ 容错（复活、回溯） | 降低弃坑率，不降低挑战 |
| ❌ 金币/钥匙 | 数值曲线失效，硬核玩家骂"氪金塔" |
| ❌ 攻击力/防御力 | 直接改变最优解，游戏变成挂机 |
| ❌ 秒杀 Boss | 通关率失真，口碑崩盘 |

### 5.2 广告点位矩阵

| ID | 点位 | 形式 | 触发时机 | 玩家得到 | 频控 | 策略影响 | 预估占比 |
|---|---|---|---|---|---|---|---|
| **A1** | 开屏 | 开屏 | 冷启动 | — | 每次启动 1 次，2s 可跳过 | 无 | 15% |
| **A2** | 层间插屏 | 插屏 | 第 5/10/15…层首次上楼 | — | 间隔 ≥180s，日 ≤8 次 | 无 | 12% |
| **R1** | 战败复活 | 激励 | HP ≤ 0 | 满血复活，保留进度 | 每层 1 次，日 ≤5 次 | 低（只回血，不回资源） | **30%** |
| **R2** | 楼层回溯 | 激励 | 任意时刻（菜单内） | 回到指定楼层的完整快照 | 每日 3 次；内购解锁无限 | **零**（重来，不给新资源） | 15% |
| **R3** | 扫荡 | 激励 | 层内，存在"必胜"怪 | 一键击杀本层所有可秒杀怪 | 每层 1 次 | 零（省点击） | 12% |
| **R4** | 路线提示 | 激励 | 任意时刻 | 高亮本层"下一步最优格" | 每层 1 次 | 低（只给一步） | 8% |
| **R5** | 宝箱 | 激励 | 每 5 层 1 个 | 金币 + 红药水 | 每 5 层 1 次 | 低（软资源） | 5% |
| **R6** | 图鉴/皮肤 | 激励 | 图鉴页 | 解锁怪物条目 / 主角皮肤 | 无限制 | 零 | 3% |
| **R7** | 每日首胜 | 激励 | 每日首次通关一层 | 该层金币 ×2 | 每日 1 次 | 低 | — |

**被明确否决的点位（写在这里防止以后有人加回来）：**

- ❌ **金币双倍（所有楼层）** —— 金币是核心资源，双倍 = 数值曲线作废
- ❌ **看广告加攻击/防御** —— 直接改最优解
- ❌ **看广告给钥匙** —— 钥匙是关卡设计的核心约束
- ❌ **常驻 Banner 压在地图上** —— 遮挡规划视野，且廉价感极强
- ❌ **每步操作后弹广告** —— 这是 IAA 游戏最常见的死法
- ❌ **宝箱强制看广告才能开** —— "可选"和"强制"的界线，就是过审和差评的界线

### 5.3 R1 战败复活：为什么它值 30%

魔塔的失败是**不可逆**的：你在第 37 层发现钥匙用完了，意味着要重玩两小时。这是整个品类最大的痛点，也是唯一一个"玩家愿意主动看 30 秒广告"的时刻。

设计细节（很重要）：

- 复活后 **HP 回满，但怪物 HP 也重置** → 等于重打这场，不是"无敌"
- **每层限 1 次**。否则玩家会无脑硬闯，丢弃"算账"这个核心乐趣
- 复活后该层进入 **"受创状态"**：后续楼层插屏广告概率提升（用频次换取体验，而不是用频率换收入）
- 面板上必须**同时显示免费出口**（回本层起点）

### 5.4 R2 楼层回溯：把"重来"做成商品

这是我认为最优雅的一个点位。它的逻辑是：

> 玩家不是不愿意重来，是不愿意**重来两小时**。
> 让"重来 5 分钟"变得廉价，广告就变得可接受。

- 每层上楼时自动存快照（HP / ATK / DEF / 金币 / 钥匙 / 道具 / 已开地图）
- 回溯列表展示最近 5 个快照，附一个"该层预估难度：★★☆"
- **回溯不返还任何资源**，只是把时间倒回去
- 内购 6 元解锁"无限回溯" —— 这是最自然的付费点，因为它卖的是**时间**，不是**数值**

### 5.5 频控与熔断

| 规则 | 值 |
|---|---|
| 单日激励视频上限 | 20 次 |
| 两次插屏最小间隔 | 180 秒 |
| 单日插屏上限 | 8 次 |
| 连续两次广告最小间隔 | 45 秒 |
| 新手保护 | **前 10 分钟 / 前 3 层，零广告**（包括开屏） |
| 熔断 | 用户连续 3 次关闭广告 → 当日不再主动弹出任何非激励广告 |

> 新手保护这一条会损失一部分短期收入，但能把次留拉高 10–15 个百分点。这是划得来的。

### 5.6 广告点位与游戏节奏的对齐

广告应该出现在**节奏的低谷**，而不是**高潮**：

```
第 1 层 ── 第 2 层 ── ... ── 第 10 层(Boss) ── 第 11 层 ...
   ↑                          ↑                    ↑
 无广告                    打完Boss，情绪释放    插屏(A2) ✓
                          不插广告 ✗

战斗中 HP 归零 ──→ R1 复活面板  ✓（痛点时刻，玩家主动看）
规划路线卡住 ──→ R4 提示按钮    ✓（玩家主动点，不弹窗）
```

### 5.7 验证方法：广告是否破坏了最优解？

做关卡时，用求解器跑两遍：
1. `最优解（不看广告）` 的剩余资源
2. `每次都看广告` 的剩余资源

如果两者差距 > 15%，说明广告点位设计有问题，必须调。**这个自动化检查应该写进关卡校验脚本。**

## 六、数值骨架（前 5 层示例，待调参）

初始：`HP 1000 / ATK 10 / DEF 10 / 金币 0 / 黄钥匙 0`

| 层 | 怪物 | HP | ATK | DEF | 金币 | 玩家损失（初始属性） | 备注 |
|---|---|---|---|---|---|---|---|
| 1 | 绿头怪 | 50 | 20 | 1 | 1 | 60 | 教学怪 |
| 1 | 小蝙蝠 | 30 | 18 | 0 | 1 | 24 | 弱，用来教"性价比" |
| 1 | 红头怪 | 70 | 25 | 2 | 2 | 120 | 稍贵 |
| 2 | 骷髅兵 | 100 | 35 | 5 | 4 | 375 | **卡点**：ATK 12 打不动，必须先拿攻宝石 |
| 3 | 石头人 | 180 | 40 | 8 | 8 | — | DEF 8，ATK 必须 ≥ 18 |
| 4 | 毒蜘蛛 | 60 | 30 | 2 | 3 | 180 | 带毒，战后 −20HP |
| 5 | 小 Boss | 400 | 55 | 10 | 30 | — | 检验 ATK ≥ 25 |

**节奏规则：**

- 每层最优解结束时，剩余 HP 应落在 **45%–70%**
- 每 5 层必须有一次"攻击力卡点"，逼玩家做资源分配
- 攻宝石投放量 ≈ 每层 +2~+4 ATK，防宝石 +1~+2 DEF
- 金币投放 ≈ 每层 15~30，商店一把蓝钥匙定价 25 金（制造"买钥匙还是买属性"的取舍）

**BOSS 设计公式：**

```
Boss.DEF = 该层玩家正常 ATK − 1     // 逼玩家把资源压到攻击上
Boss.HP  = 玩家每回合伤害 × 12~18   // 控制在 12~18 回合，太长会烦
Boss.ATK = 玩家 DEF + 一个"疼但不致命"的值
```

## 七、商业化测算

### 7.1 收入模型

参考行业公开报告的量级（[TopOn & Taku 2025 全球移动游戏广告变现报告](https://www.gamenewstc.com/nd.jsp?id=4191)），国内 Android 休闲游戏 eCPM 大致区间：

| 形式 | eCPM 区间（元） | 说明 |
|---|---|---|
| 开屏 | 15–35 | 展示量高，单价中等 |
| 激励视频 | 30–80 | 单价最高，与用户质量强相关 |
| 插屏 | 8–20 | 波动大 |
| Banner | 1–3 | 不建议用 |

> 实际以自己后台为准，TapTap 渠道的量级通常低于买量渠道。

**DAU 5,000 的日收入估算（保守假设）：**

| 形式 | 人均次数 | eCPM | 日收入 |
|---|---|---|---|
| 激励视频 | 2.2 | 45 | 495 元 |
| 插屏 | 1.2 | 12 | 72 元 |
| 开屏 | 1.0 | 20 | 100 元 |
| **合计** | | | **≈ 667 元/日** |

即 **ARPDAU ≈ 0.13 元**，月收入约 2 万元。

### 7.2 关键结论

- 这个品类**不能靠广告赚大钱**，DAU 5,000 是 2 万/月的量级
- 要靠 **TapTap 独家 + 口碑 + 长尾**，而不是买量
- 内购（去广告 6 元 / 无限回溯 6 元）在硬核用户里转化率可能到 1–3%，是更健康的现金流
- **别为了广告收入去改数值**，那会杀死口碑，而口碑是这类游戏唯一的增长引擎

## 八、合规与上架路径（这是最硬的约束）

结论先说：**没有版号，不能上 TapTap 开放下载。**

依据 [TapTap 游戏审核规范细则](https://developer.taptap.cn/docs/en/store/release/publish/agree/)：

> **1.1.1** 根据国家有关规定，未经国家新闻出版署批准的移动游戏，不得在大陆地区上线运营，即没有版号的游戏不得有任何形式的内购计费内容。

> **5.4 版号 · 特别注意**：如果游戏在大陆地区开放**预约及信息展示**，则暂不需要版号信息。如果游戏需要在大陆地区**开放下载**，请确保资质齐全。

> **5.6** 开发者需要提供 APP 备案信息。

> **5.7** 实名认证和防沉迷所提交的信息必须真实有效。

**关于"纯广告变现算不算需要版号"：** 法律上存在争议，且**实践中已有被处罚的先例**——2022 年广东肇庆公布的案例中，三款无内购、纯靠广告变现的休闲游戏，广告收益分成仅 114 元，仍以"未取得游戏版号"被行政处罚 5,000 元（详见[曼昆律所的分析](https://www.mankunlaw.com/insights/shao-shi-wei-lu-shi-yi-wen-du-dong-shang-jia-yi-kuan-mian-fei-you-xi-xu-yao-qu-de-you-xi-ban-hao-ma/)）。

### 可行的四条路径

| 路径 | 周期 | 成本 | 风险 | 适合 |
|---|---|---|---|---|
| **A. 走版号** | 6–12 个月 | 1–5 万（代理/出版服务） | 低 | 认真做长线 |
| **B. 出海** | 1 个月 | 低 | 低 | 快速验证玩法 |
| **C. 转小游戏**（微信/抖音 IAA） | 1–2 个月 | 低（备案制） | 中（政策会变） | 快速上线变现 |
| **D. TapTap 预约 + 测试服** | 即时 | 0 | 中（不能正式下载） | 先攒预约量验证市场 |

**我的建议顺序：D → C → A**

1. 先在 TapTap 开**预约页 + 开发者的话 + 实机视频**（不需要版号），验证有多少人真的想玩
2. 同时把游戏出成**微信/抖音小游戏**（Cocos 可以一键出），IAA 备案后快速上线跑数据
3. 数据跑通了，再投钱办版号，上 TapTap 正式版

> ⚠️ 另外注意 1.3 节对广告的硬性要求：不能有**无法关闭的弹窗**、不能**模仿系统通知**、广告需**显著标明"广告"**、关闭应用后不能有广告。这几点在接 SDK 时要逐条自查。

## 九、技术选型

### 9.1 引擎

**Cocos Creator 3.8**（首选）

| 理由 | 说明 |
|---|---|
| 包体小 | 空包 5–8MB，魔塔这种 2D 游戏做出来 20–30MB，对 TapTap 下载转化很关键 |
| 多端 | 一套代码出 Android / iOS / 微信小游戏 / 抖音小游戏，正好匹配上面的"路径 C" |
| 2D 够用 | 网格 + 精灵 + 补间，不需要 3D |
| TapTap 生态 | 有官方 SDK 和云存档支持 |

备选：Unity（如果后面想扩 3D 或有 Unity 经验）、Godot（免费但生态弱）。

### 9.2 广告 SDK

- **穿山甲 Pangle**（字节，国内激励视频单价最高）+ **优量汇 GDT**（腾讯）双接
- 用 **TopOn / AdSet** 做聚合，自动比价，能提升 20–40% 的填充收益
- 服务端回调（S2S）校验激励发放，防止刷广告

### 9.3 关卡求解器（重要，别跳过）

魔塔的每一层都可以形式化为状态空间搜索：

```
状态 = (位置, HP, ATK, DEF, 金币, 钥匙, 已拾取集合, 已开门集合)
动作 = 上下左右移动 / 开门 / 战斗 / 拾取 / 用道具
代价 = HP 损失
目标 = 到达上楼点
```

用 **IDA\* + 支配剪枝**（若状态 A 的每项资源都 ≥ 状态 B 且位置相同，则 B 可剪枝）在普通笔记本上几秒内就能跑完一层。

**这个工具必须在做关卡之前写出来**，否则 50 层手工调数值会陷入地狱。它同时也能跑 §5.7 的"广告是否破坏最优解"检查。

### 9.4 数据与埋点

必须埋的事件：

```
level_enter / level_clear / level_fail      # 漏斗
battle_start / battle_end                   # 数值
ad_request / ad_show / ad_complete / ad_close  # 广告漏斗
ad_placement_{A1,A2,R1..R7}                 # 分点位收益
checkpoint_load / checkpoint_restore        # 回溯使用率
hint_use                                    # 提示使用率（卡关点定位）
```

**关键指标**：D1/D7 留存、第 10 层到达率、第 30 层到达率、单层平均卡关时长、ARPDAU、激励视频观看率。

## 十一、风险清单

| 风险 | 影响 | 应对 |
|---|---|---|
| **版号** | 无法上架，直接归零 | 走 §8 的 D→C→A 路径，先小游戏跑通 |
| 品类小众 | TapTap 上魔塔类游戏 DAU 天花板低（可能 1–3 万） | 靠每日挑战 + 无尽模式做长线，不追求爆款 |
| 广告破坏体验 | 差评 + 低留存 | 严格执行 §5.1 第一原则 + §5.7 自动校验 |
| 数值失控 | 玩家卡死或太简单 | 求解器 + 每层检查清单 |
| 美术成本 | 20+ 怪物 + 50 层场景 | 用统一素材包 + 换色调，不追求每层独有素材 |
| 盗版/换皮 | 被抄 | TapTap 独家 + 品牌化命名（已改名《深潜五十》，见 v0.3 章） |

## 附二：原型已落地的界面细节（v0.2 增补）

以下细节在 `prototype/index.html` 里已经做出来了，做正式版时直接照抄，不要再重新讨论。

### 地图可读性

- **墙必须比地板暗**，不是比地板亮。走廊被"点亮"、墙体沉入黑色，玩家一眼就能看出可走路径。原型里墙 `#0d0b09→#080706`、地板 `#2f2921→#231e18`，亮度差约 2.5 倍。
- 这一条推翻了早期版本：最初墙比地板亮，结果 11×11 地图糊成一块，玩家看不出迷宫结构。**地图的可读性 = 墙地亮度差，不是装饰细节。**
- 怪物/道具/门所在格要给"走廊色"，不要用比地板更暗的底色，否则走廊会被打出缺口。

### 主角图标

- 主角必须是**唯一的人形 + 金色描边 + 呼吸动画的格子**。原型用过"蓝盾+十字"做主角，结果和图鉴里的"防御宝石"撞图标，玩家找不到自己。
- 主角格 = 金色径向底 + 1.5px 金边 + 外发光 + 2px 上下浮动。

### HUD

- 顶部：`第 N 层` + 血条（数字压在条上）+ 攻/防/金 三个 pill + 黄/蓝钥匙两个 pill。血条是唯一横贯整行的高度不变量，别在它上面加东西。
- HUD 不放经验值（本作也没有经验值）。

### 本层情报条（替代原来的道具坞）

- 地图下方那条 52px 的条，**不要放背包**（本作没有可携带消耗品），放一层的情报：`剩余怪物 / 可拾取 / 未开门`。
- 这三个数就是玩家的"还欠多少活"清单，配合底部的路线规划才有意义。数字每次 `syncHud()` 全量重算（121 格开销可忽略）。
- 右侧小字教学：`点击格子自动寻路 / 怪物角上的数是血量`。

### 战斗预判：底部 sheet + 橙色选中环

- 预判面板是**底部 sheet**（贴着屏幕底、带圆角、上方蒙层模糊 1.5px），不是浮在地图中间的卡片。
- 被点的那只怪物必须打上**橙色选中环**（`2.5px #E8873A` + 呼吸脉冲），否则玩家看完面板不知道在打谁。
- 结论条三色语义：绿 `可战` / 黄 `不划算`（战后 HP < 30%）/ 红 `会死`。红色时按钮变成 `硬打`（红底），**绝不能沿用金色**——金色会被读成"推荐"。
- 按钮文案跟着结论走：`交战` / `硬打` / `打不过`（禁用）。给结论，不只给数字。

### 商店

- 上半是**金币货架**（黄钥匙 8 / 蓝钥匙 25 / 攻宝石 30 / 防宝石 30 / 红药水 15），金币不够时整行降到 55% 不透明度、价格变灰。**不做"差一点点"的暗示弹窗。**
- 下半是**付费区**，就三件，全部是时间或外观：免广告通行证 ¥12、楼层回溯券×3 ¥6、白鲸号黑匣子 ¥6。付费区用紫色价格标签，和金币区分开。
- 文案直接写在货架下面：`付费点：这里是唯一该放内购的地方——不是卖属性，是卖「时间」。`

### 广告播放页

- 必须写清 **`奖励：<具体是什么>`**，和倒计时并排。原型最初写了"可跳过 · 2s"，和"5 秒后可领取"自相矛盾——激励视频不存在"可跳过"，这是审核会挑的错。
- 倒计时期间领取按钮 40% 透明 + `pointer-events:none`，结束后再亮。

### 图鉴

- 未击败的怪物显示剪影，计数要**动态**（`已解锁 / 总数`），别写死。
- 图鉴只给"已知数值"，**不给本层路线、不给怪物位置**，否则等于把解谜答案卖了。

### 战败面板

- 三选项顺序固定：`看广告满血复活`（金）→ `回到本层起点`（绿色"免费"角标，永远免费）→ `从第 1 层重新开始`。
- 底部固定一行：`必须有一个完全免费的出口，否则会被判「诱导」`。这不是文案，是审核红线。

## 附三：地图观感重做（v0.3.1 → v0.3.2）

第一版地图的问题是**"看起来像表格，不像空间"**。根因不是配色，是**每个格子都被当成一块独立的方块**：每格都有圆角、间隙、各自的渐变和斜面，121 个独立方块排在一起，视觉上必然是电子表格。

### 走过的两条路

**第一版（CSS 跨格纹理）**：`gap:0` + 噪点贴图按 `background-position: calc(var(--gx) * -34px)` 跨格连续 + JS 判四邻只在交界打光。视觉上确实变成了一整片岩壁，但**底色是渐变而非像素块，永远不会有"墙"的体积**。

**第二版（Canvas 统一绘制，当前采用）**：整张地图画在两张 canvas 上——`terrain-floor`（地板）与 `terrain-wall`（墙体，非墙处 `destination-out` 挖空），DOM 格子只负责放图标。

```js
// 每格 32×32 的石砖：底块 + 顶面受光 + 底/右落影 + 错缝 + 颗粒
w.fillStyle = base;                        // 三档明度按 hash 分布
w.fillRect(px, py, C, C);
w.fillStyle = 'rgba(156,201,226,.26)'; w.fillRect(px, py, C, 3);        // 顶面
w.fillStyle = 'rgba(0,0,0,.42)';       w.fillRect(px, py + C - 3, C, 3); // 底影
w.fillStyle = 'rgba(0,0,0,.52)';       w.fillRect(px, py + 15, C, 1);    // 横缝
w.fillRect(px + (k > .5 ? 11 : 21), py, 1, 15);                          // 竖缝（错位）
```

这条路的关键收获：**CANVAS 让"每格独立美术"重新变得合理**。CSS 时代每格长得一样才像表格，而像素瓦片的做法本来就是"每格一张图"，只要每格内部有体积就有读法。

### 关键数字

| 项 | 值 | 说明 |
|---|---|---|
| 格子 | 32px | 11×11 = 352px；2× 屏上正好 1:1 像素对齐 |
| 墙底色 | `#31434D / #384A55 / #40525D` 三档 | 按 `hash2(x,y)` 分布，避免复制感 |
| 地板 | `#20323C` + 噪点 | **地板比墙亮**，走廊才读得出来 |
| 顶沿受光 | 3px `rgba(156,201,226,.26)` | 只在每格顶部，不画渐变 |
| 交界遮蔽 | 14px 线性渐变 `rgba(0,0,0,.55)` | 贴墙一侧，只做地板 |
| 全局光 | 一层垂直线性渐变 | `#9FD8FF0A → #0000005E` |
| 灯光池 | `radial-gradient(circle 300px)` | 半径 ≈ 9 格，压暗上限 30% |

**压暗必须克制**：这是"全图可见"铁律，压太狠会毁掉规划感。

### 踩过的坑

- `repeating-linear-gradient` 做水面焦散，仅 6% 不透明度整张图就变成斜条纹壁纸。**大面积规则条纹在深色底上会被放大**。
- 给每个墙格加 `inset 0 2px 0` 高光 → 121 条水平亮线，迷宫结构当场消失。逐格高光只能用于**交界**，不能用于**每一格**。
- SVG `feTurbulence` 噪点 opacity 0.5 + overlay 混合过强，墙面变高对比斑块 → 降到 0.30 并改 normal。
- 截图验证浮层时要禁用 CSS 动画，否则会截到 `pop` 动画中间帧，看起来像"浮层半透明"。

### 仍然缺的

地形已经是像素瓦片了，但**角色与道具还是矢量图标**——这是目前唯一"不像游戏"的部分。见 `美术素材生产提示词包.md`。
